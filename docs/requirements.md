# 需求文档（Requirements）

本文档是 [specs/spec.md](../specs/spec.md) 的详细展开，聚焦需求拆解、角色、验收标准，供产品/研发/评审共同确认。规格的权威来源是 `specs/` 目录；本文件用于更详细的说明与示例。

## 1. 问题陈述

公司通过企业微信员工账号添加了大量客户的个人微信作为外部联系人，目前客户咨询和回访完全依赖人工客服，存在响应慢、经验难以沉淀、无法规模化的问题。希望引入 AI：

- 自动回答客户基于知识库的常见问题；
- 对低置信度/敏感问题转人工，避免错误承诺；
- 支持定期回访任务的生成、人工审核与（受控条件下）自动发送；
- 全程留痕，便于合规审计与效果评测。

## 2. 明确不做（重申）

- 不使用微信个人号协议机器人（Wechaty/Hook/协议号等）。
- 不使用 Dify、RAGFlow 等一体化平台。
- 不做加好友、拉群等主动扩列（人工完成）。
- 不在本阶段进行企业微信官方生产级联调（仅接口占位）。

## 3. 角色与权限（第一阶段简化）

| 角色 | 主要操作 | 第一阶段权限模型 |
|---|---|---|
| 客户 | 发送消息 | 无系统账号，仅作为会话中的 `external_userid` |
| 企业微信员工 | 被动接收 AI 自动回复辅助 | 无独立登录，先以 `staff_userid` 标识 |
| 人工客服/主管 | 处理转人工会话、审核回访 | 单一内部角色，无细粒度 RBAC（占位） |
| 知识库管理员 | 上传/更新文档 | 同上，占位角色 |
| 系统管理员 | 配置与运维 | 环境变量/配置文件级别 |

> 多租户与细粒度权限模型是待决策项，见 [docs/brainstorming.md](./brainstorming.md)。

## 4. 用例详情

详见 [specs/spec.md](../specs/spec.md) §3。此处补充验收标准的可测试化描述：

### UC-1 客户咨询 AI 自动回复
- **Given** 知识库中存在与客户问题高度相关的文档片段
  **When** 客户发送该问题
  **Then** 系统返回的回答引用了该文档片段的来源标识
- **Given** 客户问题命中敏感关键词黑名单
  **When** 消息被处理
  **Then** 系统不生成业务性回答，标记会话为 `handoff_required`
- **Given** 企业微信回调因网络重试，同一 `msg_id` 投递两次
  **When** 两次都到达消息入口
  **Then** 系统只处理一次，第二次返回幂等确认而不重复调用 LLM 或重复发送

### UC-2 知识库摄取与检索
- **Given** 上传一篇 Markdown 文档
  **When** 摄取完成
  **Then** 可通过检索接口用相关查询词命中该文档的至少一个片段，且返回片段带 `source_id`

### UC-3 回访任务
- **Given** 回访任务处于 `pending_review` 状态
  **When** 未经审核
  **Then** 系统不会调用发送接口
- **Given** 人工批准回访任务
  **When** 系统执行发送（占位实现）
  **Then** 任务状态迁移为 `sent` 或 `failed`，并记录审计

### UC-4 人工接管
- **Given** 会话被标记 `handoff_required`
  **When** AI 收到新消息
  **Then** AI 不再自动回复，直到人工显式交还

### UC-5 审计与评测查询
- **Given** 一段时间内发生了若干次 AI 交互
  **When** 调用评测/日志查询接口
  **Then** 返回的记录不包含未脱敏的客户隐私字段（如手机号/身份证号原文）
