# 脑暴议题与待决策清单

以下问题需要在后续迭代中与业务/合规/企业微信管理员共同确认，第一阶段骨架不假设任何结论。

## 1. 企业微信能力确认

- [ ] 当前企业微信主体已开通的具体权限（客户联系 API / 客服消息 API / 会话内容存档）范围？
- [ ] 消息回调的加解密算法版本、Token/AESKey 轮换策略？
- [ ] 自动回复允许的会话时间窗口（如 48 小时规则）在当前配置下的实际生效范围？
- [ ] 主动发送（回访/关怀）消息的频率限制、消息类型限制、每日群发总量限制？
- [ ] 语音/图片/文件类消息的接入是否是必须需求，优先级如何？

## 2. 客户会话内容存档与授权

- [ ] 是否需要开通会话内容合规存档能力？是否需要客户知情同意/提示？
- [ ] 存档内容的访问权限、保留期限、导出/删除流程？

## 3. 主动回访消息的官方限制

- [ ] 回访消息是否必须走“客户联系-群发”能力，还是可用其他官方接口？
- [ ] 触达频率上限、被投诉/拉黑的处理流程？
- [ ] 是否需要在回访内容中提供“取消订阅/不再打扰”选项？

## 4. 模型供应商

- [ ] 首选模型供应商（如 DeepSeek、通义千问兼容模式、OpenAI、自托管 vLLM）及其成本/延迟/合规性对比？
- [ ] 是否需要多供应商路由（未来可引入 LiteLLM）？
- [ ] embedding 模型是否需要私有化部署（数据不出境要求)？

## 5. 知识库更新流程

- [ ] 知识库内容的来源（人工整理 / 现有文档系统导入）与更新频率？
- [ ] 是否需要版本管理、审核流程、失效文档的下线机制？
- [ ] 文档格式支持范围（PDF、Word、网页）优先级？

## 6. 人工客服工作台边界

- [ ] 人工客服是否需要独立前端界面，还是复用企业微信自身会话界面 + 后台管理系统？
- [ ] 转人工后的通知机制（企业微信应用消息、短信、内部系统）？
- [ ] 人工回复是否需要经过系统留痕（供审计/评测）？

## 7. 多租户与权限

- [ ] 是否有多个企业主体/部门的隔离需求？
- [ ] 角色权限模型（RBAC）细化需求，例如知识库管理员 vs 回访审核员？

## 8. 数据保留策略

- [ ] 客户消息、审计日志、评测数据集的保留期限？
- [ ] 客户主动要求删除数据（如适用法规）的处理流程？
- [ ] 备份与灾难恢复策略？

## 9. 其他

- [ ] 是否需要客户满意度调研/评价收集？
- [ ] 与现有 CRM/工单系统的集成需求与优先级？
- [ ] 上线前是否需要在测试企业环境完整跑通一次真实企业微信联调？
